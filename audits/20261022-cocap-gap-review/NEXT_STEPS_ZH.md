# 面向投稿的后续计划与 agent 流程

2026-10-22。建议基于本轮原文审计；不代表已经实现或实验成立。

## 1. 先把文章的可证明主张收窄

可以研究“局部目标信息下，轻量邻居信号怎样协调临时多人支援，并减少捕获带来的覆盖损失”。不要写“首次搜索与捕获结合”“首次同质动态角色”“首次衰减证据招募”。FSC2、AIS、W-MAPPO 和早期信息素研究已经覆盖这些宽泛叙事的不同版本。

三个可选侧重点应由实验选择，而不是全部同时宣称：

| 侧重点 | 应给出的关键证据 | 不足时怎么处理 |
|---|---|---|
| 信息效率 | 不发送隐藏目标坐标时，与坐标转发/无支援信号的捕获、覆盖及总消息负载对比 | 只比较一个标量的大小，不能声称系统总通信更低；图与友机状态也计入 |
| 协作有效性 | 支援是否缩短落后目标等待、补足角度缺口，同时避免过量聚集 | 若仅捕获率提高而覆盖更差，应诚实讨论代价，不能说优化了机会成本 |
| 任务连续性 | 相同机器人捕获后重用，覆盖恢复时间，重复到达任务的长期服务情况 | 有限批抓完截图不够；尚无实验就列未来工作 |

不要把已有手工路由称为“完全自动涌现角色”，也不要把信号解释成已学出的捕获概率。若需要 capturability-aware 贡献，必须新增对应定义、模型与验证；这会显著扩大文章工作量，当前不建议仅为叙事补一条新技术线。

## 2. 执行顺序及交付物

1. **冻结比较合同。** 写清目标/队友/障碍观测、消息内容、图的构造地点与范围、动作约束、正常捕获及异常失活。列出原算法和改造版的差异。
2. **完成最小可信 baseline。** TERL 保留；AIS-PGM 先做原生行为预检，DBI 备选；必要时补 kWTA 显式分配参照。每条产出实现说明、参数来源、原生核验记录、共同环境适配清单。未跑通之前不扩训练矩阵。
3. **拆开机制贡献。** 无信号、无/弱支援、相同网络与不同奖励结构等对照要回答独立问题。凡信号和奖励尺度同时变化，必须拆开，不用一条合并消融归因。
4. **统一正式评测。** 同种子、目标策略、障碍布局、预算；报告失败与置信区间。捕获、碰撞、等待、资源占用、覆盖恢复和消息/计算成本共同解释结果。
5. **据结果定论文。** 若优势主要来自信息接口，则围绕信息效率写；若来自几何闭合，则围绕受约束协作写；若优势不稳，先解释失败和补必要机制，不再靠增加关键词强化标题。

以上是依赖顺序，没有伪造工期；代码可用性、原文歧义和已有训练质量尚会影响实际成本。

## 3. 后续 agent 怎样筛到真正需要的文章

建议保持仓库的 SEARCH → SCREEN → READ 与 MASTER 单写者规则，但新增两道明确门槛：

**SEARCH 先写任务卡。** 一张卡包括：目标起初未知吗；传的是目标坐标、标量还是共享观测；机器人同质吗；捕获需要几个人及什么几何；是否释放；是否恢复覆盖；对手是否主动逃逸；动作与障碍条件。每路负责一个缺口，不按 UAV/USV 名称重复搜索。

**SCREEN 必须用原文证据淘汰“名称相似”。** 最少检查模型、观测式、成功判据和实验设置；每个结论给页码/章节。下列情况不能直接列主 baseline：单目标被综述归在多目标节、整体包围目标中心被当成逐目标捕获、单机接触被当多人闭合、全队广播被当严格局部、目标因模型设定自动停止、只有 preview 却写 READ。

**READ 再决定是否值得实现。** 对留下的文章取 PDF 或完整正文；记录版本、来源和哈希。由主 agent 阅读关键原文，尤其检查子 agent 认为最接近和最不利于创新的文章。只看子 agent 的总结不算主审。主 baseline 还需检查代码/参数/求解器缺口，代码链接存在不等于可运行。

推荐机器可读交付字段：

```text
paper_id / DOI / canonical_version / source_url / source_kind / sha256
observation_contract / exchanged_content / graph_construction
homogeneity / dynamics / target_policy / capture_event / release_event
restoration_event / repeated_arrivals / theory_assumptions / hardware_scope
primary_locations / facts / inferences / unresolved / baseline_adaptations
decision / decision_reason / child_review_scope / master_review_scope
```

每篇分别给出三种判断，不能用一个“匹配度 90%”混在一起：**创新威胁程度、共同任务匹配程度、复现可行性**。FSC2 威胁高但连续改造难；AIS 任务匹配高但实现细节需预检；TERL 动作/判据最接近但原目标信息更强。这样的结论才能直接支持工程决策。

检索停止依据应是预定论点的证据充分，而不是达到论文数量。当前可以先停止扩大普通学习 baseline，进入复现；如果文章最后主打 density 分配或 coverage–tracking 新颖性，则必须先补 SDI/Luo 原文。每次出现新强近邻，都允许修订旧结论，保留改动缘由和旧记录。
