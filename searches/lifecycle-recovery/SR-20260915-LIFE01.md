# FS-LIFE-01 SEARCH Handoff — Post-Capture Release / Return-to-Coverage Lifecycle

## Scope
- Topic: post-capture resource release, coalition/role dissolution, return to patrol/coverage/search, and readiness for repeated/changing threats.
- Taxonomy nodes: lifecycle bridge across persistent patrol/coverage/search; dynamic coalition formation/release; pursuit/capture; continual task allocation; repeated intrusion/defense.
- Search round ID: FS-LIFE-01 / SR-20260915-LIFE01
- Date: 2026-09-15
- Repo baseline checked before search and again before commit: `main` at `9b0b2531711bb6ec0e4e9be65811fbe794b47a4b` before this handoff commit.
- Search stage only. No `Pxxxx` IDs assigned; no canonical files edited; no SCREEN/READ decisions made.

### Narrow question

Has prior work already implemented or formally analyzed the event-driven lifecycle

`persistent patrol/coverage/search`
→ `target/threat detection`
→ `temporary pursuit/capture subgroup formation`
→ `capture/task completion`
→ `coalition/role dissolution or resource release`
→ `return to patrol/coverage`
→ `ready for repeated/changing target arrivals`?

The test used here is **task-completion-triggered resource cycling**, not generic multi-tasking, not generic dynamic task allocation, and not merely continuing to another already-known target.

### Negative controls inherited from the repo

The search deliberately did **not** count the following as direct lifecycle hits:
- concurrent monitoring + encirclement without a terminal event (P0010 class);
- fixed scouts continuing exploration while fixed pursuers pursue (P0033 class);
- captured-target agents moving to another already-present target (TERL/P0035 class);
- externally induced robot add/remove robustness (P0008 class);
- one-shot capture/interception followed by episode termination (P0012/P0034 class);
- generic MRTA/coalition formation without a pursuit/capture completion trigger;
- patrol→pursuit without an explicit return/recovery transition.

### Hit count under a strict definition

- **0** papers found that clearly close the entire seven-stage lifecycle in one system with the same fungible resource pool.
- **1 strict Direct lifecycle hit** for an explicit `capture/apprehension completion → nominal patrol return` transition: Bradshaw et al. (2008).
- **2 additional strong completion→release/reuse structural hits**: Liu et al. (2025) and HECTOR (2026), but neither explicitly returns the released capture coalition to area patrol/coverage in the CoCap sense.
- **5 strong repeated-event/repeated-threat sources** among the retained set: Liu, HECTOR, Duarte, Chandler, Bajaj.

[AI判断] Therefore a standalone claim such as “first post-capture return to patrol” is dead. A stronger integrated claim around **same-pool coverage↔capture resource cycling under repeated arrivals**, especially when coupled to local/uncertain belief and capturability-aware recruitment, still survives this SEARCH.

## NEW PAPERS

### 1. Construction of kill webs with heterogeneous UAV swarms in dynamic contested environments
- **Authors / first author:** Wenlin Liu; Zishuang Pan; Wei Han; Xichao Su; Dazhao Yu; Bing Wan / Wenlin Liu.
- **Year / venue / status:** 2025, *Complex & Intelligent Systems*, published (online 2024-11-09; Vol. 11, article 8).
- **DOI:** `10.1007/s40747-024-01644-4`.
- **Preliminary class:** **Partial lifecycle hit — strongest structural analogue**.
- **Candidate map node:** completion-triggered temporary coalition dissolution + recurrent/pop-up target replacement.
- **Exact nominal mission:** heterogeneous UAV kill-web operation; UAVs can remain in an **uncommitted** state with sneak-like movement in the mission space when not committed to a target.
- **Target/threat arrival model:** simulation maintains target demand by introducing a **pop-up target when a target is destroyed**, keeping target count unchanged.
- **Target number:** example uses 60 UAVs and 4 targets; destroyed targets are replaced by randomly generated same-type pop-up targets.
- **Detection/event trigger:** target/task availability drives decentralized coalition bidding/formation; exact onboard target-sensing modality is not the contribution surfaced in SEARCH and should be normalized in SCREEN.
- **Pursuit/engagement subgroup formation:** bottom-up dynamic consensus-based coalition/auction mechanism (DCBCA) forms a temporary combat coalition around a target.
- **Dynamic membership:** yes; task commitments and coalition structures are dynamically negotiated using local-neighbor information/adaptive communication.
- **Capture/task-completion definition:** synchronized strike/destruction once coalition members reach their assigned positions; this is a strike/neutralization task, not PE capture.
- **Local completion or whole episode:** local target task completion; simulation continues.
- **Nonparticipants:** remain uncommitted or engaged with other targets/tasks.
- **After completion:** **explicitly, the coalition dissolves and each UAV returns to the uncommitted state**.
- **Coalition dissolution:** **explicit yes**.
- **Explicit return/resume patrol/coverage:** **no**. `uncommitted` is not shown to be a coverage/patrol controller; do not silently relabel it as coverage.
- **Reassignment:** yes; uncommitted resources can participate in later target coalitions.
- **Repeated/new arrivals:** **yes**, via pop-up target replacement after destruction; the simulation reports continued kill-web operation across several destroyed/replaced targets.
- **Communication:** distributed/local-neighbor information with adaptive communication in the coalition algorithm.
- **Sensing:** target-state acquisition details are not normalized at SEARCH depth; SCREEN must inspect assumptions.
- **Centralized/distributed:** distributed coalition formation/allocation.
- **Method family:** optimization / consensus / auction / dynamic coalition formation.
- **Simulation / real experiment:** simulation evidence surfaced; no physical experiment identified in this SEARCH.
- **CoCap structural relevance:** very high for `completion → dissolve → reusable pool → next target`; lower for `return to coverage` and for pursuit-capture semantics.
- **Evidence location:** Springer full-text sections describing UAV engagement states and DCBCA coalition execution; simulation section explicitly states coalition dissolution after synchronized strike and pop-up target replacement after destruction.
- **Why it matters:** this paper directly kills any claim that task completion followed by coalition dissolution/release into a reusable resource pool is itself novel.

### 2. Accelerated K-Serial Stable Coalition for Dynamic Capture and Resource Defense
- **Authors / first author:** Junfeng Chen; Zili Tang; Meng Guo / Junfeng Chen.
- **Year / venue / status:** 2024, *IEEE Robotics and Automation Letters* 9(1):443–450, published.
- **DOI / arXiv:** `10.1109/LRA.2023.3334560`; arXiv `2305.15729`.
- **Preliminary class:** **Partial lifecycle hit — strongest capture-specific competitor**.
- **Candidate map node:** continual heterogeneous exploration + capture + resource defense with dynamic coalition reassignment.
- **Exact nominal mission:** large heterogeneous territory-defense system: UAV-like SCOUT robots explore/detect; SWAT robots capture intruders or defend resources.
- **Target/threat arrival model:** tasks are generated/changed online; intruders are described as entering from unknown positions and moving continuously. The SEARCH evidence does not establish a clean stochastic target-arrival distribution, so do not overstate one.
- **Target number:** large-scale example includes more than 50 unknown target robots and 100 unknown resources; another reported run captures 234 targets over 200 time steps.
- **Detection/event trigger:** SCOUT exploration/detection and online task generation create capture/defense tasks; SWAT robots may switch defense→capture when a target is nearby.
- **Pursuit subgroup formation:** KS-COAL forms task-specific stable coalitions; capture uses multiple SWAT robots and geometric/Apollonius reasoning.
- **Dynamic membership:** yes, via online coalition formation/reassignment.
- **Capture/task-completion definition:** **capture task finishes when the target robot is captured and becomes immobile**.
- **Local completion or whole episode:** local capture-task completion; system continues with many tasks.
- **Nonparticipants:** SCOUT robots continue exploration; other SWAT robots may defend resources or serve other capture tasks.
- **After completion:** robots are part of an online reassignment framework, but an explicit sentence `capturing coalition dissolves and returns to patrol/exploration` was **not** located in SEARCH.
- **Coalition dissolution:** dynamic coalitions/reassignment yes; **post-capture dissolution specifically requires SCREEN verification**.
- **Explicit return/resume patrol/coverage:** not verified; roles are heterogeneous, and SCOUT exploration is a separate role.
- **Reassignment:** yes, central to the online task-allocation/coalition framework.
- **Repeated/new arrivals:** repeated capture workload is clearly demonstrated; exact exogenous new-target arrival process remains unclear.
- **Communication:** important caveat: within SCOUT and SWAT teams the paper assumes free/unlimited communication in the surfaced preprint, even though coalition decisions are decentralized/local in structure.
- **Sensing:** SCOUT robots provide long-range exploration/perception; normalize exact target-information sharing in SCREEN.
- **Centralized/distributed:** distributed/decentralized coalition/task allocation.
- **Method family:** distributed coalition formation / task allocation / geometric capture.
- **Simulation / real experiment:** large simulation plus reported 13-robot hardware experiment.
- **CoCap structural relevance:** extremely high for concurrent exploration/capture/defense, dynamic capture coalitions, explicit local task completion, and resource reassignment; weaker for same-agent return-to-coverage and strict local target belief.
- **Evidence location:** arXiv/full text task definitions and scenario; capture-task completion sentence; journal/institutional metadata for publication and hardware evidence.
- **Why it matters:** closest capture-specific precursor found for `online tasks → temporary capture coalition → completion → continued resource allocation`, but it does not yet close the explicit `capture coalition → coverage role` transition.

### 3. HECTOR: Human-Centric Hierarchical Coordination and Supervision of Robotic Fleets Under Continual Temporal Tasks
- **Authors / first author:** Shen Wang; Yinhang Luo; Jie Li; Meng Guo / Shen Wang.
- **Year / venue / status:** 2026, *IEEE Transactions on Automation Science and Engineering* 23:8276–8295, published.
- **DOI / arXiv:** `10.1109/TASE.2026.3683709`; arXiv `2604.10892`.
- **Preliminary class:** **Partial lifecycle hit — strongest continual-task dissolution/reassignment result**.
- **Candidate map node:** continual temporal missions + dynamic capture coalition + completion-triggered dissolution/reassignment.
- **Exact nominal mission:** heterogeneous fleet executes an ongoing stream of missions/subtasks including delivery, surveillance, and dynamic capture.
- **Target/threat arrival model:** missions are released online at random times; the reported setup uses five missions with inter-arrival times drawn from a positive-truncated normal distribution (mean 32.5 s, SD 5 s).
- **Target number:** dynamic-capture examples contain many moving subtasks/targets (e.g. 18 moving subtasks served by a 22-robot team; mission examples around 17 moving targets).
- **Detection/event trigger:** online mission/subtask release; for moving capture subtasks, current target positions are assumed available through external sensing/tracking rather than discovered by the coalition itself.
- **Pursuit subgroup formation:** dynamic coalition formation (DCF) uses local information and peer communication to form subteams for collaborative pursuit/capture.
- **Dynamic membership:** **yes**; fleet repeatedly reshapes coalitions across subtasks.
- **Capture/task-completion definition:** completion of the moving capture subtask. In numerical task semantics, completion is tied to the specified task action, not a PE no-escape theorem.
- **Local completion or whole episode:** local subtask completion; continual mission stream continues.
- **Nonparticipants:** other robots/subteams continue other mission subtasks.
- **After completion:** **explicitly, coalitions dissolve upon subtask completion and robots are reassigned**; a worked example shows two robots completing a joint subtask then separating to different subsequent subtasks.
- **Coalition dissolution:** **explicit yes**.
- **Explicit return/resume patrol/coverage:** **no**. Reassignment is to the broader subtask pool, not specifically to nominal patrol/coverage.
- **Reassignment:** **explicit yes**.
- **Repeated/new arrivals:** **explicit yes**, continual online random mission arrivals.
- **Communication:** peer communication/local information inside DCF; human-supervision layer above.
- **Sensing:** moving-target positions may be externally tracked/known; not a local-belief competitor.
- **Centralized/distributed:** hierarchical human-centric supervision with distributed/local coalition formation at execution level.
- **Method family:** hierarchical task planning / dynamic coalition formation / continual MRTA.
- **Simulation / real experiment:** numerical/large-fleet experiments surfaced in SEARCH; physical validation not identified here.
- **CoCap structural relevance:** extremely high for `completion → coalition dissolve → reassignment → continual arrivals`; does not demonstrate return-to-coverage or strict pursuit-capture semantics.
- **Evidence location:** full-text DCF section and large-fleet experiment; exact statement that coalitions dissolve upon subtask completion and robots are reassigned; continual-mission release model in experimental setup.
- **Why it matters:** proves that completion-triggered coalition dissolution and reuse under continual arrivals is already a mature-looking MRTA/coordination primitive, even if the nominal task is not persistent coverage.

### 4. Coordination in Human-Agent-Robot Teamwork
- **Authors / first author:** Jeffrey M. Bradshaw; Paul J. Feltovich; Matthew J. Johnson; Larry Bunch; Maggie R. Breedy; Thomas C. Eskridge; Hyuckchul Jung; James Lott; Andrzej Uszok / Jeffrey M. Bradshaw.
- **Year / venue / status:** 2008, International Symposium on Collaborative Technologies and Systems (CTS), published.
- **DOI:** `10.1109/CTS.2008.4543966`.
- **Preliminary class:** **Direct lifecycle hit** under the narrow TASK definition.
- **Candidate map node:** explicit post-apprehension mission transition back to patrol.
- **Exact nominal mission:** mixed human/robot security team in a Navy-pier field exercise performs patrol/search and intruder apprehension under policy-governed teamwork.
- **Target/threat arrival model:** scenario-level intruder event; repeated stochastic arrivals are not modeled.
- **Target number:** intrusion scenario; no multi-target/repeated-arrival model established in SEARCH.
- **Detection/event trigger:** intruder detection and team/commander coordination trigger apprehension tasking/subteam action.
- **Pursuit subgroup formation:** team structures/roles can be created or modified dynamically; robots can be assigned to subteams for apprehension.
- **Dynamic membership:** yes at the teamwork/policy level; not a formal autonomous coalition optimization result.
- **Capture/task-completion definition:** intruder **apprehended**; team members are notified of successful goal completion.
- **Local completion or whole episode:** successful team goal within a continuing field-exercise mission architecture.
- **Nonparticipants:** broader team remains governed by shared policies; exact concurrent coverage metric is not defined.
- **After completion:** **all teams are notified; each robot begins its appropriate post-success task, with explicit examples `return to base` or `resume patrolling`.**
- **Coalition dissolution:** formal dissolution wording was not located; practical resource/role transition after successful goal is explicit.
- **Explicit return/resume patrol/coverage:** **yes — resume patrolling is explicit.**
- **Reassignment:** yes through policy/team-role tasking.
- **Repeated/new arrivals:** not demonstrated/modelled.
- **Communication:** policy-governed team notifications/coordination; detailed radio topology is not the key contribution and should be normalized in SCREEN.
- **Sensing:** field-exercise sensing stack not normalized in this SEARCH.
- **Centralized/distributed:** mixed human-agent-robot teamwork; not purely autonomous decentralized control.
- **Method family:** behavior/policy-based human-agent teamwork / organizational control.
- **Simulation / real experiment:** **real field exercise** with two humans and five robots.
- **CoCap structural relevance:** decisive prior for the isolated `successful apprehension → resume patrol` transition, but much weaker for autonomous coalition formation, multi-target assignment, repeated arrivals, coverage optimization, or capturability.
- **Evidence location:** full text, field-exercise/team-policy section around the post-apprehension notification and post-success task policy.
- **Why it matters:** this is the clearest evidence found that **post-capture return to patrol itself is not a new lifecycle idea**.

### 6. Hybrid Control for Large Swarms of Aquatic Drones
- **Authors / first author:** Miguel Duarte; Sancho Moura Oliveira; Anders Lyhne Christensen / Miguel Duarte.
- **Year / venue / status:** 2014, *Artificial Life 14* conference proceedings, published.
- **DOI:** `10.7551/978-0-262-32621-6-ch127` (see uncertainty note below regarding a conflicting ResearchGate DOI rendering).
- **Preliminary class:** **Partial lifecycle hit / important near miss**.
- **Candidate map node:** persistent patrol → local detection → temporary pursuit → return to patrol → repeated intruders.
- **Exact nominal mission:** large aquatic-drone swarm continuously patrols a maritime surveillance strip.
- **Target/threat arrival model:** after an initial period, intruders cross at random locations every 30 minutes; reported 24-hour run contains 44 crossings.
- **Target number:** repeated individual intruder crossings over time.
- **Detection/event trigger:** local intruder detection; detecting robot alerts nearby drones within a 200 m radius.
- **Pursuit subgroup formation:** alerted nearby drones enter `Pursue Intruder`; behavior drops surplus pursuers so roughly two remain.
- **Dynamic membership:** yes, behaviorally/emergently.
- **Capture/task-completion definition:** **none**. Intruder leaving the patrol zone or loss/timeout terminates pursuit.
- **Local completion or whole episode:** local pursuit termination; 24-hour patrol mission continues.
- **Nonparticipants:** large majority continue patrol; reported steady state is dominated by patrolling drones.
- **After pursuit:** if a drone has not seen the intruder for five minutes it returns to Patrol; pursuers also stop once intruder exits the patrol zone and reintegrate spatially relative to neighbors.
- **Coalition dissolution:** implicit behavioral dispersal; not capture-triggered.
- **Explicit return/resume patrol/coverage:** **yes**, but triggered by loss/exit/timeout rather than successful capture.
- **Reassignment:** return to patrol state.
- **Repeated/new arrivals:** **yes**, 44 repeated intruder crossings in the reported run.
- **Communication:** local alert broadcast to nearby drones; decentralized swarm interaction.
- **Sensing:** onboard/local sensing including camera/GPS assumptions in the hybrid swarm setup.
- **Centralized/distributed:** decentralized hybrid controller with evolved behaviors and a preprogrammed state arbitrator.
- **Method family:** behavior-based / evolutionary swarm robotics / hybrid systems.
- **Simulation / real experiment:** long-duration large-swarm simulation in the reported lifecycle experiment.
- **CoCap structural relevance:** very high for persistent `patrol → pursue → return → next intruder`; fails the crucial **capture-completion trigger**.
- **Evidence location:** ALIFE full text sections defining Patrol/Pursue states, five-minute return, intruder schedule, and 24-hour performance.
- **Why it matters:** demonstrates that almost the whole persistent lifecycle exists in swarm surveillance once capture is removed; this is an important near miss, not a direct hit.

- **Target/threat arrival model:** an arbitrary number of intruders may be released from the boundary at arbitrary time instants and locations.

## TAXONOMY CHANGES

The focused search suggests the lifecycle branch should explicitly separate these concepts rather than using a single `dynamic roles` label:

1. **Completion-triggered release vs generic online reassignment** — a robot can be dynamically reassigned without any completed capture task.
2. **Resource release vs nominal-task restoration** — `coalition dissolves → uncommitted` (Liu) is not the same as `coalition dissolves → patrol/coverage` (Bradshaw-style return).
3. **Return-to-nominal vs remaining-target reassignment** — TERL-style `captured A → go to target B` is a separate category and must not count as recovery.
4. **Same-pool/fungible lifecycle vs fixed-role persistence** — fixed scouts continuing patrol while fixed pursuers fight is weaker than the **same agents** being recruited out of and released back into a nominal coverage pool.
5. **Repeated-arrival model taxonomy** — distinguish (a) pop-up replacement after destruction; (b) continual random mission releases; (c) periodic/random intruder crossings; (d) Poisson alerts; (e) arbitrary-time adversary release.
6. **Return trigger taxonomy** — distinguish successful capture/task completion; alert servicing; target loss/timeout; target exits region; mission cancellation.
7. **Capture semantics within lifecycle papers** — distinguish PE/physical capture, immobilization, synchronized strike/destruction, apprehension, geometric/behavioral `Capture` mode, and mere alert-site servicing.
8. **Lifecycle maturity axis** — track separately: nominal mission, detection, temporary coalition, terminal event, dissolution/release, nominal-task return, repeated-arrival readiness.

[AI判断] This taxonomy is necessary because the strongest false positives differ by exactly one missing edge. It also prevents a broad novelty claim from surviving merely by relabeling `uncommitted`, `reassigned`, or `go to next target` as `return to coverage`.

## SEARCH GAPS

### Remaining exact intersection

No searched paper clearly demonstrated all of the following in one same-pool system:

`persistent area coverage/search`
